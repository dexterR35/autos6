# Audit: parts, payments and supporter features (19 November 2026)

Scope: everything added on 18–19 November (part lifecycle, monthly support, votes, share
cards, spending page, digest, admin tools) plus the Stripe payment paths they touch,
checked against Stripe's current documentation (API `2026-09-30.endive`, the version the
installed `stripe@23` library uses). Fixes are in
`supabase/migrations/20261119120000_audit_fixes.sql` and the code, with tests in
`tests/audit-fixes.test.js`.

## Fixed

| # | Severity | Problem | Fix |
| --- | --- | --- | --- |
| 1 | High | **Chargebacks were ignored** (also before these features). A disputed payment kept counting toward totals and could mark a part Funded. | `charge.dispute.*` webhooks: disputed money leaves all totals; won (or won on appeal, inquiry closed, prevented) restores it; lost keeps it out. | 2 | High | **RON payments under 2.00 lei** would be rejected by Stripe (its minimum charge for RON is 2.00), showing "payment provider unavailable". | Per-currency minimum in the browser and in the database (one-time and monthly); parts can be finished with one minimum contribution. |
| 3 | Medium | **Manage monthly support**: the confirmation page told supporters to bookmark it, but the checkout id is removed from the address (privacy), so the bookmark never worked; and the id-based billing link never expired. | Link from a checkout now works for 2 days; long-term access uses Stripe's own email + one-time-code portal login (`VITE_STRIPE_PORTAL_LOGIN_URL`), shown on the Donations page. |
| 4 | Medium | A **monthly checkout paid by bank debit** (e.g. SEPA) completes as `unpaid` but was marked active. | Stays pending until `invoice.paid`. |
| 5 | Medium | **Switching currency** while a checkout in the old currency could still complete would drop that payment from all totals. | Currency stays locked while any checkout from the last 25 hours is open. |
| 6 | Low | Share-page meta used `String.replace` with the part name in the replacement: a name containing `$&` would inject the old tag's raw HTML into `<head>` (owner-controlled text only). | Replacer functions; regression test with a hostile name. |

## Verified against Stripe docs (no change needed)

- Invoices on API ≥ 2025-03-31: subscription and its metadata are under
  `invoice.parent.subscription_details`; `invoice.payment_intent` is gone and is read from
  `GET /v1/invoice_payments?invoice=…` (`payment.type = payment_intent`). Older webhook
  versions (`invoice.subscription`, `invoice.payment_intent`) are handled too.
- Checkout subscription mode: `subscription_data.metadata` / `description`,
  `consent_collection.terms_of_service`, `custom_text` are valid; `payment_method_types`
  (removed in endive) is not used; `customer_creation` isn't set (not allowed in subscription mode).
- Apple Pay / Google Pay on Stripe-hosted Checkout need no domain registration.
- Webhooks: signature verified on the raw body, livemode checked, every event deduplicated
  by id in the database, out-of-order delivery handled (invoice before checkout, refunds
  before payment), non-2xx only for retryable failures.
- Dispute statuses match Stripe's enum (`warning_*`, `needs_response`, `under_review`,
  `appeal_*`, `won`, `lost`, `prevented`).

## Accepted risks / for you to decide

- **Vote stuffing**: one vote per confirmed email; someone with many email addresses can
  vote many times. Fine for advisory votes; for binding ones, limit to people who donated.
- **Donor update emails** start without a second confirmation (the donor ticked the box
  at checkout and gave the email to Stripe). Every email has an unsubscribe link.
- **Receipts are public** once uploaded (public storage bucket); removing one from a part
  doesn't delete the file. Redact before uploading.
- **Monthly payments with a different amount** (coupon, plan change) are held for review;
  keep plan switching off in the customer portal.
- A monthly payment Stripe settles without a PaymentIntent (e.g. paid from customer credit
  balance) is recorded but its later refund can't be matched automatically (logged).
- The legal text was updated for the new features; have it reviewed before launch.
